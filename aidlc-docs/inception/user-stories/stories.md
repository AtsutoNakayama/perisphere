## Epic E1: 画像入力

### US-01 エクイレクタングラー画像の表示

- **ペルソナ**: P1 / P2 ／ **優先度**: In MVP ／ **トレース**: FR-01
- **ストーリー**: As a 組み込み開発者, I want エクイレクタングラー（2:1）の JPEG/PNG を渡すだけで全天球として表示したい, so that 360°写真をアプリに最小手数で載せられる。
- **受け入れ基準**:
  - Given アスペクト比 2:1 の JPEG/PNG を指定した状態で / When ビューワーを初期化する / Then 全天球パノラマとして歪みなく表示され、初期化完了イベントが発火する。
  - 2:1 でない画像を渡した場合は明確なエラー（不正入力）として扱い、フォールバック表示に倒す。

### US-02 8K を動作保証ラインとし上限なしで読み込む

- **ペルソナ**: P1 ／ **優先度**: In MVP ／ **トレース**: FR-01, NFR-01
- **ストーリー**: As a 組み込み開発者, I want 8K までは滑らかさを保証しつつ、それを超える画像も上限エラーで拒否されずに読み込みを試みてほしい, so that 高解像度素材でも一律に弾かれず扱える。
- **受け入れ基準**:
  - Given 7680×3840（8K）のエクイレクタングラー画像 / When 表示する / Then 主要対象環境で視点操作・ズームが滑らか（60fps 目安）に動作する。
  - Given 8K を超える画像 / When 読み込む / Then API は寸法上限で一律拒否せず読み込みを試み、実行環境の WebGL 最大テクスチャサイズを超える場合はエラーイベント通知＋安全なフォールバックに倒す。
  - 8K 超の滑らかさ・メモリ・成否は環境依存であり性能保証の対象外であることがドキュメントに明記される。

### US-03 URL 指定での画像読み込み

- **ペルソナ**: P1 ／ **優先度**: In MVP ／ **トレース**: FR-01
- **ストーリー**: As a 組み込み開発者, I want 画像を URL 指定で読み込みたい, so that CDN やストレージ上の素材を直接表示できる。
- **受け入れ基準**:
  - Given CORS 対応の画像 URL / When 読み込む / Then 画像が取得・表示され、読み込み進行イベントが発火する。
  - CORS 非許可・404・ネットワーク失敗時は読み込みエラーイベントを発火し、フォールバック表示に倒す（US-32 と整合）。

### US-04 入力フォーマットの拡張アダプタ（インターフェース）

- **ペルソナ**: P3 ／ **優先度**: In MVP（拡張点の公開） ／ **トレース**: FR-02, NFR-05
- **ストーリー**: As a 拡張開発者, I want 画像ソースの解釈（テクスチャ生成）を交換可能な抽象として扱いたい, so that 新しい入力フォーマットをコア改修なしに足せる。
- **受け入れ基準**:
  - Given 公開された入力アダプタ・インターフェース / When 独自アダプタを実装・登録する / Then コア本体を変更せずに新しい画像ソースを解釈できる。
  - 初期実装のエクイレクタングラーも同じアダプタ機構の上に実装されている。

### US-05 将来の入力ソース追加（キューブマップ等）

- **ペルソナ**: P3 ／ **優先度**: Future ／ **トレース**: FR-02（スコープ外表）
- **ストーリー**: As a 拡張開発者, I want キューブマップ・デュアルフィッシュアイ・360°動画等を将来追加したい, so that 入力の幅をコミュニティで広げられる。
- **受け入れ基準**:
  - 初期リリースでの実装はスコープ外。US-04 のアダプタ・インターフェースで追加可能な構造が確保されている。

## Epic E2: ビューワーモード

### US-06 既定の標準ビュー表示

- **ペルソナ**: P2 ／ **優先度**: In MVP ／ **トレース**: FR-03
- **ストーリー**: As a エンドユーザー, I want 既定で見慣れた標準ビューで表示してほしい, so that 特別な操作なしに自然な 360°体験から始められる。
- **受け入れ基準**:
  - Given モード未指定 / When ビューワーが初期化される / Then 標準ビュー（球の中心からの透視投影）で表示される。

### US-07 広視野系モードの選択と投影特性（UltraWide / Dewarp / Linear / Panini）

- **ペルソナ**: P2 ／ **優先度**: In MVP ／ **トレース**: FR-03
- **ストーリー**: As a エンドユーザー, I want 広視野系の投影モードを選びたい, so that 用途に応じて視野角と歪みのバランスを変えられる。
- **受け入れ基準**:
  - Given ビューワー表示中 / When UltraWide / Dewarp / Linear / Panini のいずれかを選択する / Then 表示が当該投影の見た目特性（UltraWide=広視野で周辺歪み許容、Dewarp=広視野で歪み軽減、Linear=直線が直線のまま、Panini=広視野かつ垂直線の直線性を保つ）を満たす。
  - 各モードで視点操作（E3）が破綻なく機能する。

### US-08 特殊表現モードの選択と投影特性（Tiny Planet / Crystal Ball）

- **ペルソナ**: P2 ／ **優先度**: In MVP ／ **トレース**: FR-03
- **ストーリー**: As a エンドユーザー, I want 小惑星・クリスタルボールのような表現モードを選びたい, so that 印象的な見せ方で 360°写真を楽しめる。
- **受け入れ基準**:
  - Given ビューワー表示中 / When Tiny Planet を選択する / Then 球全体が「小さな惑星」状（ステレオグラフィック投影）に見える。
  - When Crystal Ball を選択する / Then 球を外側から眺めガラス玉のように見える。
  - いずれのモードでも視点操作（E3）が破綻なく機能する。

### US-09 モード横断で視点操作が破綻しない

- **ペルソナ**: P2 ／ **優先度**: In MVP ／ **トレース**: FR-03
- **ストーリー**: As a エンドユーザー, I want どのモードでも一貫してパン・チルト・ズームできてほしい, so that モードを変えても操作に迷わない。
- **受け入れ基準**:
  - Given 7 モードのいずれか / When パン・チルト・ズームを行う / Then 表示が破綻（裏返り・固着・発散）せず連続的に追従する。

### US-10 モード切替 API（即時切替＋イベント）

- **ペルソナ**: P1 ／ **優先度**: In MVP ／ **トレース**: FR-04
- **ストーリー**: As a 組み込み開発者, I want 実行時にモードを切り替える API がほしい, so that アプリの UI からモードを制御できる。
- **受け入れ基準**:
  - Given ビューワー初期化済み / When モード切替 API を呼ぶ / Then 表示が即時に切り替わり、モード切替イベントが発火する。

### US-11 将来のアニメ遷移を見据えた切替 API 形状

- **ペルソナ**: P1 ／ **優先度**: Future ／ **トレース**: FR-04（スコープ外表）
- **ストーリー**: As a 組み込み開発者, I want 将来スムーズなアニメーション遷移を足せる API 形状にしてほしい, so that 後方互換を保ったまま演出を拡張できる。
- **受け入れ基準**:
  - 初期は即時切替のみ実装。切替 API はオプション引数（遷移指定等）を将来追加できる形状で定義されている。

### US-12 カスタムビューワーモードの登録

- **ペルソナ**: P3 ／ **優先度**: In MVP ／ **トレース**: FR-05, NFR-05
- **ストーリー**: As a 拡張開発者, I want 独自の投影モードを定義して登録したい, so that 標準にない見せ方をコア改修なしに追加できる。
- **受け入れ基準**:
  - Given 公開されたモード登録 API / When カスタムモードを登録する / Then 同梱モードと同じインターフェースで選択・表示できる。
  - 同梱 7 モード自体もこの登録機構の上に実装されている（拡張機構の実用性が担保される）。

  - Given デスクトップ表示中 / When ホイールを操作する / Then FOV/ズームが滑らかに変化し、設定された上下限内に収まる。

- **受け入れ基準**:
  - Given モバイルブラウザ表示中 / When 1 本指でドラッグする / Then 視点が連続的に追従して移動する。

### US-16 ピンチによるズーム

- **ペルソナ**: P2 ／ **優先度**: In MVP ／ **トレース**: FR-07, FR-09
- **ストーリー**: As a エンドユーザー（モバイル）, I want ピンチで拡大縮小したい, so that スマホでもズームできる。

  - Given モバイルブラウザ表示中 / When ピンチ操作する / Then ズームが滑らかに変化し、上下限内に収まる。

### US-17 キーボードによる主要操作

- **ペルソナ**: P2 ／ **優先度**: In MVP ／ **トレース**: FR-08, NFR-04
- **ストーリー**: As a エンドユーザー（キーボード利用者）, I want キーボードだけで主要操作を完結したい, so that マウス・タッチが使えなくても利用できる。
- **受け入れ基準**:
  - Given 既定キーマップ / When キーボードで操作する / Then 視点移動・ズーム・フルスクリーン切替・モード切替・写真切替が行える。

### US-18 写真の前後選択移動（矢印キー）

- **ペルソナ**: P2 ／ **優先度**: In MVP ／ **トレース**: FR-08
- **ストーリー**: As a エンドユーザー, I want 矢印キーで前後の写真へ移動したい, so that 複数写真を素早く見て回れる。
- **受け入れ基準**:
  - Given ギャラリーに複数写真 / When 矢印キー（または設定キー）を押す / Then 前後の写真へ移動し、写真切替イベントが発火する。

### US-19 キーマップの変更・無効化

- **ペルソナ**: P1 ／ **優先度**: In MVP ／ **トレース**: FR-08
- **ストーリー**: As a 組み込み開発者, I want キー割り当てを変更・無効化したい, so that アプリ既存のショートカットと衝突させずに済む。
- **受け入れ基準**:
  - Given 設定 API / When キーマップを変更または無効化する / Then 指定どおりにキー操作の有効/無効・割り当てが反映される。

### US-20 ズーム範囲（FOV）上下限の設定とモード既定

- **ペルソナ**: P1 ／ **優先度**: In MVP ／ **トレース**: FR-09
- **ストーリー**: As a 組み込み開発者, I want ズームの上限・下限を設定したい, so that 用途に合わせて行き過ぎた拡大縮小を防げる。
- **受け入れ基準**:
  - Given 上下限を設定 / When ズーム操作する / Then 範囲外には到達しない。
  - 未設定時は各モードに適した既定範囲が適用される。

## Epic E4: フルスクリーン

### US-21 フルスクリーン切替（API / UI / キーボード）とイベント

- **ペルソナ**: P1 / P2 ／ **優先度**: In MVP ／ **トレース**: FR-10
- **ストーリー**: As a エンドユーザー, I want フルスクリーンに切り替えたい, so that 没入感のある 360°体験ができる。
- **受け入れ基準**:
  - Given Fullscreen API 対応環境 / When API・UI ボタン・キーボードのいずれかでフルスクリーンを切り替える / Then 表示がフルスクリーン化／解除され、状態変化イベントが発火する。

- **ペルソナ**: P2 ／ **優先度**: In MVP ／ **トレース**: FR-10
- **ストーリー**: As a エンドユーザー（iOS Safari 等）, I want フルスクリーン非対応環境でも近い体験がほしい, so that 環境差でも破綻せず使える。
- **受け入れ基準**:
  - Given Fullscreen API 非対応環境 / When フルスクリーンを要求する / Then 代替動作（擬似フルスクリーン等、設計で確定）にフォールバックし、状態は一貫して通知される。

## Epic E5: ギャラリー（複数写真）

### US-23 ギャラリー API（リスト・next/prev・index・イベント）

- **ペルソナ**: P1 ／ **優先度**: In MVP ／ **トレース**: FR-11
- **ストーリー**: As a 組み込み開発者, I want 複数写真を API で制御したい, so that 自前の UI からギャラリーを操作できる。
- **受け入れ基準**:

  - リスト端での `next()`/`prev()` の挙動（ループ有無）が定義されている。

### US-24 標準ギャラリー UI（サムネ / インジケータ・非表示・スタイル）

- **ペルソナ**: P2 ／ **優先度**: In MVP ／ **トレース**: FR-12
- **ストーリー**: As a エンドユーザー, I want サムネイルやインジケーターで写真を選びたい, so that 一覧から目的の写真へ素早く移動できる。
- **受け入れ基準**:
  - Given 標準ギャラリー UI / When サムネイル/インジケーターを操作する / Then 対応写真へ切り替わる。

### US-25 バーチャルツアー拡張点

- **ペルソナ**: P3 ／ **優先度**: Future（拡張点の確保は In MVP） ／ **トレース**: FR-13（スコープ外表）
- **ストーリー**: As a 拡張開発者, I want ホットスポットから別写真へ遷移するツアーを将来足したい, so that バーチャルツアーをコア改修なしに実装できる。
- **受け入れ基準**:
  - 初期リリースでの実装はスコープ外。シーングラフへのオーバーレイ配置と相互作用の拡張点が確保されている。

- **受け入れ基準**:
  - Given マウント済みビューワー / When 破棄 API を呼ぶ / Then WebGL コンテキスト・イベントリスナー・テクスチャが確実に解放される。

### US-32 公開 API の入力検証

- **ペルソナ**: P1 ／ **優先度**: In MVP ／ **トレース**: NFR-10（SECURITY-05, SECURITY-11）
- **ストーリー**: As a 組み込み開発者, I want 不正な入力を明確なエラーで受けたい, so that 誤用を早期に気づける。
- **受け入れ基準**:
  - Given 公開 API / When 型・範囲・形式が不正な入力（不正画像 URL、巨大画像、悪意ある寸法等）を渡す / Then 明確なエラーとして扱い、フェイルセーフに倒す。

### US-33 フレームワーク非依存コア＋アダプタ分離

- **ペルソナ**: P3 ／ **優先度**: In MVP（core + react） / Future（vue 等） ／ **トレース**: NFR-05, NFR-07
- **ストーリー**: As a 拡張開発者, I want コアと React アダプタが分離していてほしい, so that 将来 Vue 等のアダプタをコア改修なしに足せる。
- **受け入れ基準**:
  - Given `@perisphere/core` と `@perisphere/react` の分離構成 / When 新アダプタ（例: `@perisphere/vue`）を追加する / Then コアを改修せずにアダプタを実装できる。
  - 拡張点（入力フォーマット・ビューワーモード・入力デバイス・将来のツアー/動画）が公開インターフェースとして定義されている。

## Epic E8: 横断的品質（観察可能な NFR）

### US-34 SSR セーフ

- **ペルソナ**: P1 ／ **優先度**: In MVP ／ **トレース**: NFR-03
- **ストーリー**: As a 組み込み開発者（Next.js）, I want SSR 環境で import してもエラーにならないでほしい, so that サーバーサイドレンダリングを壊さず導入できる。
- **受け入れ基準**:
  - Given SSR 環境 / When モジュールを import しサーバーでレンダリングする / Then ブラウザ API（window/document/WebGL）へアクセスせずエラーなく描画され、ビューワー本体はクライアントマウント後に初期化される。

### US-35 アクセシビリティ（キーボード完結・フォーカス・ARIA）

- **ペルソナ**: P2 ／ **優先度**: In MVP ／ **トレース**: NFR-04（FR-08, FR-15）
- **ストーリー**: As a エンドユーザー（支援技術利用者）, I want キーボードと支援技術で操作・把握したい, so that アクセシブルに 360°写真を利用できる。
- **受け入れ基準**:
  - Given 支援技術／キーボード / When ビューワーと UI を操作する / Then 主要操作がキーボードのみで完結し、フォーカス管理と ARIA 属性が適切で、文言は差し替え可能。

### US-36 性能体感（8K で 60fps 目安）

- **ペルソナ**: P2 ／ **優先度**: In MVP ／ **トレース**: NFR-01
- **ストーリー**: As a エンドユーザー, I want 操作が滑らかであってほしい, so that 快適に見回せる。
- **受け入れ基準**:
  - Given 8K までの画像・主要対象環境 / When パン・チルト・ズームする / Then 視点操作・ズームが滑らか（60fps 目安）に保たれる。

### US-37 障害分離・縮退（読込失敗 / コンテキストロスト復帰）

- **ペルソナ**: P2 ／ **優先度**: In MVP ／ **トレース**: NFR-11（RESILIENCY-10, FR-18）
- **ストーリー**: As a エンドユーザー, I want 一部の失敗で全体が巻き込まれないでほしい, so that 復帰可能な状態で使い続けられる。
- **受け入れ基準**:
  - Given 画像読み込みの失敗・タイムアウト / When 発生する / Then ビューワー全体を巻き込まず縮退し、安全な状態を保つ。
  - Given WebGL コンテキストロスト / When 発生する / Then 復帰を試み、不能ならフォールバック表示に倒す。

## 制約・注記（ストーリー化しない開発・運用方針 / 方針 Q5=C）

以下の NFR は「ユーザーが観察する振る舞い」ではなく開発・配布・運用の方針のため、ストーリー化せず制約として記録する（後続の Workflow Planning / Construction で扱う）。

- **NFR-02 対象環境**: Desktop（Chrome/Edge/Firefox/Safari 最新世代）・Mobile（iOS Safari / Android Chrome）、WebGL 2 前提。ジャイロ操作は初期スコープ外（入力拡張点で将来対応）。各ストーリーの「主要対象環境」はこれを指す。
- **NFR-06 依存方針**: three.js は peerDependencies、サポート版を package.json とドキュメントに明記。ランタイム依存は最小限。
- **NFR-07 配布形態**: npm 公開、ESM + 型定義、tree-shaking 可能。CDN/UMD は初期スコープ外。（拡張性の観察可能部分は US-33 でカバー）
- **NFR-08 ドキュメント・デモ**: API リファレンス・全モード体験デモ・React/Next.js サンプルを整備。
- **NFR-09 テスト戦略**: PBT 全面適用。投影計算・座標変換・状態管理（ギャラリー・モード切替）が主対象。ビジネスクリティカルなパスは example-based 併設。フレームワーク選定は Construction で確定。
- **NFR-10 セキュリティ（残余）**: サプライチェーン（lockfile・脆弱性スキャン・バージョン固定・公式レジストリ）。観察可能部分は US-30/US-31/US-32 でカバー。
- **NFR-11 レジリエンシー（残余）**: RTO/RPO = N/A（稼働サーバーなし）。変更管理は GitHub Flow + 正式版リリース時のリリースブランチ。観察可能部分は US-30/US-37 でカバー。
- **NFR-12 ライセンス・OSS 運用**: MIT、Conventional Commits、CONTRIBUTING のブランチ運用。
- **命名ポリシー**: 公開 API・UI・ドキュメントの名称は一般的な投影用語または独自の中立名のみとし、第三者の商標・製品名・ブランド名を使用しない。
